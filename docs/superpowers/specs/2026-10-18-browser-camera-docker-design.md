# Kamera browser dan Docker untuk uji Mac

User approved adding Aktifkan kamera to the existing kiosk and Docker Compose for the Mac built-in camera. Browser getUserMedia supplies JPEG frames to a loopback-only Flask container; no USB passthrough or host Python. Reuse the kiosk layout, existing recognition pipeline, encrypted queue and server policy. API e-office remains an external configured HTTPS staging service, not a newly provisioned empty e-office installation.

Default Compose must start without proprietary models or credentials and support a clearly labelled camera preview/transport trial that NEVER records attendance. Full e-office trial requires explicit configuration, deployed model assets, key and staging credential; no simulated recognition, bypass or reenrollment. Persist instance data in a named volume, exclude secrets/models/data from image context, do not auto-reset queues or keys. Missing prerequisites must be explained.

Browser sessions must be bounded, same-origin, CSRF protected, single-owner, expire and release on stop/disconnect; frame bytes/dimensions bounded. No browser employee IDs or capture dates accepted. Short-lived single-use server-issued frame challenges bound freshness; reject stale/replay and reset recognition across sessions/gaps. Retain acquisition time before decode/inference. At most one frame in flight, no raw-frame persistence/backlog. Container/HTTP/browser timestamps are an estimate of acquisition, not independently verified hardware capture; this is a local trial only, physical and spoof acceptance remains blocked.

UI includes activate/stop, local muted inline preview, permission/not-found/busy/network errors, no automatic permission prompt, cleanup on hide/unload, disabled controls during transitions, no attendance success from frame acknowledgements. Internet outage to e-office preserves existing durable queue; browser-to-container failure stops new capture and does not store browser frames for later attendance.
